# Contributing

Thanks for your interest in contributing to Employee Learning Management System!

By contributing you help make this project better for everyone. The following guidelines will help us review and merge your work faster.

## How to Contribute

1. Fork the repository.
2. Create a feature branch from main:
   ```bash
git checkout -b feature/short-description
```
3. Make your changes in the feature branch. Keep commits small and focused.
4. Run tests and linters locally.
5. Push your branch and open a Pull Request against the repository's main branch.

## Pull Request Checklist

- [ ] The PR has a clear title and description explaining the why and what.
- [ ] The code follows project style and conventions.
- [ ] Tests have been added or updated for new behavior.
- [ ] All existing tests pass.
- [ ] No sensitive data or secrets are included.

## Coding Style

- Follow PEP 8 for Python code.
- Use meaningful variable and function names.
- Add docstrings to public functions and classes.
- Keep functions small and single-purpose.

## Tests

- Add unit tests for new features and bug fixes.
- Run tests locally:
  ```bash
python manage.py test
```

## Commit Messages

Use clear, present-tense commit messages. Example:
```
Add course allocation bulk API
```

## Reporting Bugs

If you find a bug, open an issue and include:
- A clear, descriptive title
- The steps to reproduce
- Expected and actual behavior
- Relevant logs or screenshots

## Requesting Features

Open an issue describing the feature, why it is useful, and any design suggestions or mockups.

## Code Review

Be responsive to review comments. Maintain a respectful tone and be open to iteration.

Thanks for helping improve the LMS!
